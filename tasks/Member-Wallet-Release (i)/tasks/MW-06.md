# MW-06 - Bank Profile / Withdrawal Requests - ONE PR

**PR title:** `fix(flow-3): implement member withdrawal requests`
**Depends on:** MW-05.

## Scope
- Member can save/edit payout bank details in account wallet settings (bank code/name, beneficiary account number/name), with masking, server validation, minimal access and re-confirmation at withdrawal. Do not ask bank OTP/PIN/login. Sensitive details are never placed in notification bodies or ordinary logs.
- Member submits withdrawal amount from withdrawable (verified, non-simulated) wallet balance; atomically reserve available funds on `PENDING` request. Reject zero/negative/excess amounts, missing account, concurrent requests exceeding balance, tampering with userId or payout account.
- Receptionist assigned role can see pending withdrawals, `APPROVE` or `REJECT` with reason. Approval must NOT automatically mark transfer completed. Separate `complete` step requires verified reference and actor/time (or explicit `SIMULATED_COMPLETED` demo-only, without real financial movement). Reject/failure releases reserve exactly once; complete consumes reserve once.
- Keep standard package refund's Manager approval workflow distinct; do not hijack its permissions. Add withdrawal status/history into wallet ledger read layer for MW-08.

## Acceptance
1. Amount can be withdrawn only if backed by eligible non-simulated funds. Demonstration-only funds cannot be sent as real bank payouts.
2. Receptionist can approve/reject withdrawal; Member/Coach cannot authorize; replay does not duplicate payout.
3. `APPROVED` -> not yet transferred; `COMPLETED` requires recorded settlement evidence. Reserved funds not spendable.
4. Reject or failure returns funds to available exactly once.

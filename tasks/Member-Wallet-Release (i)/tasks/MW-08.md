# MW-08 - Member Payment and Wallet History - ONE PR

**PR title:** `fix(flow-3): expose member payment and wallet history`
**Depends on:** MW-07.

## Scope
- Expose two clearly labeled views or unified filtered timeline: **Payments & Receipts** (existing Cash/Bank/QR payments, package purchase/refund) and **Wallet Activity** (QR top-up PENDING/confirmed, debit for wallet purchase, any compensation credit, withdrawal reserve/approved/completed/rejected/released). Do not replace existing receipt semantics or mix revenue and wallet deposits.
- Rows show timestamp in center timezone, type, amount exact VND, debit/credit (where meaningful), payment method/source, transaction ID, status, and running/resulting balance if authoritative. Detail links reveal only Member-owned records; hide full bank numbers; clearly label SIMULATED.
- Add sensible date/status/type filters, pagination/limits if history grows, empty/loading/error states, and direct links from Wallet Overview and existing member payment nav. Pending top-ups must never appear as usable credits; approved-but-not-paid withdrawals are not completed.
- Member should see all *own* wallet usage and recorded non-wallet payments without cross-Member leakage. Replayed events produce no duplicates. Reconcile ledger sum to authoritative wallet balance. Preserve existing printable receipts/invoices if present.

## Acceptance
1. Member can view transaction history and wallet history any time with own role.
2. Filter by status/type and review detail; no missing pending/failed vs success differentiation.
3. At least one top-up, purchase, compensation (if applicable), withdrawal and Bank/QR/Cash example demonstrated with synthetic fixture or honestly noted if not executable.
4. Backend verifies ownership on every list/detail; no sensitive data leakage or fabricated running balance.

- Screenshot A: Member Payment History list with filters/statuses.
- Screenshot B: Wallet Activity timeline with top-up, debit, withdrawal states; optional screenshot transaction detail.
- Reconciliation test, cross-account access test and final cross-flow E2E evidence.

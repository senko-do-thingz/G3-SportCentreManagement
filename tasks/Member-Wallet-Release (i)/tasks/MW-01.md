# MW-01 - Member Profile & Password - ONE PR

**PR title:** `fix(flow-1): complete member profile and password updates`
**Depends on:** latest `origin/main`.

## Scope
- Audit/reuse `MyProfilePage`, `profileValidation`, `memberApi`, backend `PUT /users/me`, `PUT /users/me/password`. Do not rebuild a feature already working.
- Verify Member can edit name, DOB, phone, address, goals and level anytime while signed in; save to authoritative DB and show persistent values after refresh/logout-login. Check date validation, blank/null optional fields, duplicated email not silently changed, and cross-user authorization.
- Verify password change current-password validation, strong rules, confirmation, revocation/logout of old tokens, old password rejection and new login success. Avoid logging secrets or exposing passwords in screenshots.
- Keep initial signup minimal; do not force bank or health answers in signup. Add clear navigation to detailed Profile/Health/Wallet sections as available without broken links.

## Acceptance
1. Valid edit persists server-side; invalid future DOB and malformed data rejected without partial update.
2. Other Member cannot update or view profile; inactive session cannot mutate.
3. Successful password change revokes old auth and UI guides relogin; wrong current password leaves old password intact.
4. UI remains usable on Desktop 1440x900; no full-page visual overhaul.

## Tests & screenshot evidence
- Unit/integration: profile validation, PUT semantics, password-token lifecycle, scope and rejected mutations; real browser GET/edit/save/reload.
- Screenshot A: editable Member My Profile with synthetic DOB and fields.
- Screenshot B: saved persistent profile after reload, or password change successful logged-out state; optional third screenshot invalid DOB.
- Screenshots README and PR body as required in `03_DESKTOP_EVIDENCE_AND_REVIEW.md`.

## Out of scope
New wallet ledger, medical diagnosis, broader signup redesign or unsolicited role changes.

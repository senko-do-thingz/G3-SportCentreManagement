# MW-07 - Receptionist Operational Inbox - ONE PR

**PR title:** `fix(flow-1): add receptionist action inbox`
**Depends on:** MW-06.

## Scope
- Reuse existing notification table/service patterns for persistent role-scoped Receptionist inbox + top bar unread badge; action card with title, event time, role-scoped link and current task state. Do not build email/SMTP/push/messaging or a second independent inbox domain.
- Generate notifications for Top-up needing verification, Member Withdrawal needing review, payment/booking refund exceptions and new support request (if existing workflows expose hooks). For other routine Receptionist work, extend only where a real persisted actionable event exists. Do not invent notifications of completed tasks as pending work.
- Deduplicate per business event/transition and recipient assignment. `mark read` must not approve/resolve task. Task resolution comes from source operation state; show current state upon opening. Disabled staff cannot see new data; multiple staff cannot duplicate approve/complete actions.
- Use local polling/manual refresh (e.g. sensible 15-30s frequency) only when needed; efficient bounded query and clear empty/error state. Local desktop only.

## Acceptance
1. When relevant top-up/withdrawal reaches pending state, eligible Receptionist sees one actionable notice with proper link.
2. Repeated requests/refresh do not cause duplicate notices or fake unread counts.
3. Read and resolved are separate; a read pending task remains pending until business action occurs.
4. User roles denied outside Receptionist assigned rights; concurrency safe work resolution.

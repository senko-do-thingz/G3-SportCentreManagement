# 13 - Figma to Database Schema Gap Analysis
This document provides a comprehensive audit of all 135 Figma screens from the refreshed context/ directory against Flyway migrations (V1 to V19) and the application backend architecture.

## 1. Executive Summary and Gap Matrix

### 1.1. Status Definitions
- **COVERED**: Full-stack complete. Both the underlying database schema (tables, columns, foreign keys, constraints) AND the needed backend REST API endpoints, DTOs, and services are implemented in the code repository.
- **PARTIAL**: Database schema is fully created in Flyway migrations (V1-V19), but backend REST controllers, DTOs, or service workflows are not yet fully implemented (scheduled for subsequent sprint tasks).
- **MISSING**: Neither the schema nor the backend exists (0 screens, as all 135 screens have their schema tables implemented in V1-V19).
- **LEGACY-CONFLICT**: UI assumes legacy schema constructs that conflict with modern design (0 screens).

### 1.3. Schema-Only Coverage (Database Layer)
- **Database Tables Implemented**: 58 tables total (26 tables in V1-V12 + 32 tables in V13-V19).
- **Sequences Implemented**: 11 sequences total across all modules.
- **Screens with Schema Support**: 135 out of 135 screens have dedicated tables, columns, foreign keys, and constraints defined in migrations V1-V19.
- **Full-Stack Implementation Rate**: 40 COVERED (29.6%), 95 PARTIAL (70.4%), 0 MISSING (0.0%).

## 3. Inventory of Missing Schema Elements

### 3.1. Missing Columns on Existing Implemented Tables
1. **`sport_package.session_minutes`**: Required to store duration per session (60 minutes for self-training, 90 minutes for coach-led). Currently specified only in `description` text. Needs column `SMALLINT NOT NULL CONSTRAINT df_sport_package_session_minutes DEFAULT 60 CONSTRAINT ck_sport_package_session_minutes CHECK (session_minutes IN (60, 90))`.
2. **`member_card.payment_id`**: Foreign key to `payment(id)` to link membership card purchase/upgrade transactions.
3. **`sport_package_registration.payment_id`**: Foreign key to `payment(id)` to link package registration purchases.
4. **`refund_request.payment_id`**: Foreign key to `payment(id)` to link the original payment being refunded, plus `refund_payment_id` for disbursement.

### 3.2. Missing Tables (32 Planned Tables)
#### Payments, Invoices and POS (Module 3)
- `payment`: Stores transaction records, payment methods (CASH, CREDIT_CARD, BANK_TRANSFER, MOMO, VNPAY, ZALOPAY), payment status (PENDING, SUCCESS, FAILED, REFUNDED), gateway references, and amounts.
- `invoice`: Official billing document storing subtotal, discounts, VAT tax, grand total, and issue status (ISSUED, PAID, CANCELLED, REFUNDED).
- `invoice_line`: Detailed line items (item_type, description, quantity, unit_price, line_total).

#### Class Waitlists (Module 2)
- `waitlist_entry`: Queue entries when class sessions reach max capacity (status: WAITING, OFFERED, PROMOTED, EXPIRED, CANCELLED, offer countdown timestamps).

#### Training, Attendance and Progress (Module 4)
- `session_plan`: Structured training curriculum for classes.
- `session_plan_step`: Drill steps within training plans (drills, duration minutes, instructions).
- `attendance_record`: Individual member session attendance (status: PRESENT, ABSENT, LATE, EXCUSED, marked timestamp).
- `attendance_correction`: Receptionist / manager audit trail for corrected attendance statuses.
- `skill_metric`: Standardized performance metrics per sport (e.g. passing accuracy, swim pace).
- `session_result`: Member performance evaluations per session.
- `session_result_score`: Metric breakdown scores per evaluation.
- `coach_feedback`: Qualitative feedback, ratings (1-5), strengths, and notes from coaches to members.

#### AI Workout Recommendations (Module 5)
- `recommendation_rule_set`: AI rule configurations and active versioning.
- `recommendation_rule_weight`: Parameter weights for matching goals to workout curriculums.
- `workout_plan_candidate`: Candidate recommendation plans generated for member questionnaires.
- `workout_plan`: Formal workout plans adopted by members.
- `workout_plan_week`: Plan weekly phases.
- `workout_plan_day`: Daily training routines.
- `workout_plan_exercise`: Specific exercises (sets, reps, rest seconds, video URL, completion status).
- `plan_review`: Coach review queue for personalized feedback and plan adjustments.

#### AI Assistant and Helpdesk (Module 6)
- `assistant_setting`: Chatbot system configuration.
- `assistant_topic`: FAQ knowledge base topics and response templates.
- `assistant_quick_prompt`: Quick starter prompt chips displayed on chat UI.
- `ai_conversation`: Chat session records with satisfaction ratings.
- `ai_message`: Message thread history (USER vs ASSISTANT, timestamps).
- `support_request`: Helpdesk tickets escalated from AI or submitted by staff (status: OPEN, IN_PROGRESS, RESOLVED, CLOSED, priority: LOW, MEDIUM, HIGH, URGENT).
- `support_request_message`: Discussion thread between member and support staff on a ticket.

#### System, Notifications and User Interests
- `notification`: System notifications pushed to members and staff.
- `announcement`: Centre-wide broadcast bulletins.
- `system_setting`: Global operational parameters.
- `member_sport_interest`: Member preferred sports for personalized discovery.
- `coach_sport`: Multi-sport coaching qualifications.

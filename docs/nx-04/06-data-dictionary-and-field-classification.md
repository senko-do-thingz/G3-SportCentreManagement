# Data dictionary and field classification

Status: PROPOSED for all P_ records and new field groups. Existing E_ fields are SOURCE_CONFIRMED in [inventory](02-existing-schema-reuse-inventory.md), principally S04. These are candidate review aliases, not approved DDL. Every proposed object below is conditional on D-11 adoption, D-10 contract agreement and specific physical approval in addition to its named decisions.

Classes: I = internal identifiers/operational metadata; P = personal training information; R = restricted narrative/audit context; C = shared curriculum after explicit authorized publication. Nothing is public by default. Nullable means candidate storage possibility, never silent zero/default permission. Durations, field lengths, enums, delete/archive rules and retention are TBD_AFTER_APPROVAL unless explicitly identified as existing facts.

## Projection allowlists (all PROPOSED)

Member plan view: own permitted assignment, revision identity, approved curriculum title/steps and context. Exclude recipient lists, peer identifiers, staff notes, editor-only metadata and unpublished drafts. Member result/attendance view: own session/date, approved outcome/values/unit, approved participation label and correction summary only. Member progress view: approved member_comment and approved assessment fields; never serialize staff_note by loading the entity directly. Coach view: current authorized session/member context plus necessary permitted values; historic access and private-note access remain separate decisions.

Receptionist keeps existing arrival projection only. Manager keeps existing roster/log projections as observed; a new training projection requires explicit D-12 approval. Future exports use the same row and field predicates and separate D-12.PRIVACY_OPERATIONS approval. D-14 does not allow training narratives into AI providers. No private content goes into entity_code, summary, correlation token or logs by default proposal.

## Shared metadata, lifecycle and missing values

Candidate created/changed instants are server-generated with selected UTC precision; actor identity is resolved from an authenticated current account, never trusted from a client field. A revision sequence is not a timestamp; a rowversion token is not retention metadata. Optional fields remain absent unless policy explicitly admits NULL. For metric values distinguish not measured, omitted, invalid and numeric zero; do not coerce strings or accept scaffold bounds as clinical/training rules. These meanings require D-03.VALIDATION and D-10.

No retention duration, correction window, automatic hard delete, archival state enum or export entitlement is selected. Existing cascades are observed, not extended into new history. Any future erasure must reconcile FK safety, legal/business retention, member history and audit minimization through D-03.RETENTION and D-12.PRIVACY_OPERATIONS. Time conversions and backfills require provenance; ambiguous legacy server-local timestamps must stay explicitly unverified rather than be falsely labeled UTC.
